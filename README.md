# endstone-antiphantom

Endstone 幻翼生成偏好插件。每位玩家可以设置自己的偏好；插件使用当前玩家位置和服务器 `tick-distance`，判断一个区块是否应限制幻翼生成。

## 玩家使用

- `/phantom on`：开启幻翼生成偏好，允许生成。新玩家默认为 **on**。
- `/phantom off`：关闭幻翼生成偏好，请求在你的模拟候选范围内禁止生成。
- `/phantom status` 或 `/phantom`：显示自己的偏好、当前位置的插件限制，以及实际原因。

**on 表示允许幻翼生成。** 关闭偏好不等于当前位置一定禁止生成：如果覆盖同一区块的任何玩家开启了偏好，插件仍不限制该区块。查询会列出这些玩家的名字。

判定规则：

1. 只检查同维度、当前模拟候选范围覆盖目标区块的在线玩家。
2. 有至少一位覆盖玩家开启偏好：不限制生成。
3. 有覆盖玩家，且全部关闭偏好：取消幻翼生成事件。
4. 没有覆盖玩家：保留原版行为。

玩家消息为中文。设置按照 UUID 保存，改名、重连和重启不丢失偏好；只有成功保存后才提示“已保存”。

### 能力边界

- 本插件只影响幻翼生成事件，不清理现有幻翼，不阻止幻翼飞入，不提供免受攻击保护。
- “不限制生成”不代表一定生成。自然生成仍需全局 `doinsomnia` 开启，并满足原版的其他条件。本插件不修改该规则，也无法通过当前公开 API 读取它的运行时值。
- Endstone 当前没有提供生成原因，所以插件不能区分自然生成、刷怪蛋和命令生成。经过同一事件的这些来源都会受规则影响。
- 范围是玩家模拟**候选**区块，不是所有已加载区块，也不保证候选区块已经就绪或每个实体实际参与了 tick。

## Server setup

- Source version: `0.1.0`; pure-Python wheel, Python **3.11–3.15**.
- Endstone API: `0.11`; implementation and tests use **Endstone 0.11.14**.
- Geometry evidence is specific to **Linux x86-64 BDS 1.26.52.3**. Other BDS builds/platforms need geometry verification even if the Python API loads successfully.
- Build using `python -m pip install build` and `python -m build`. Place the resulting `dist/endstone_antiphantom-0.1.0-py3-none-any.whl` in your Endstone `plugins` directory, then restart the server.
- The host supplies Endstone. The plugin has no additional runtime dependencies, native hooks, scheduled tasks, or movement listeners.

The plugin reads `server.properties` from the server process working directory **at enable time**. Standard Endstone launchers use the BDS directory. A custom launcher must use the same directory as the BDS configuration. Restart after changing `tick-distance`; the plugin does not hot-reload it or attempt to query BDS internals.

A missing `tick-distance` key defaults to 4. An integer is clamped to **4..12**, including odd values, with an English warning when clamped. Malformed, duplicate, or non-integer values and unreadable/missing files disable the plugin with a clear English log message; they are not silently replaced by defaults. The reader accepts ordinary `key=value` syntax, surrounding whitespace, and whole-line `#`/`!` comments. It does not interpret inline comments or Java-properties escaping.

### Permissions and console

`antiphantom.command` defaults to `true` and permits changing only the caller's preference and querying their current chunk. There are no administrator overrides, other-player setters, or parent/child permission trees. Permission is checked in the command handler so its denial messages can follow the sender's language; the command may remain visible when permission is denied.

Console and other non-player senders receive English help. They cannot set a preference or query an invented “current console chunk.” Server logs and permission descriptions are English.

### Stored data and recovery

`plugins/antiphantom/preferences.json` (the host-provided plugin data folder) contains schema version 1 and UUID-to-boolean preferences. Unknown players default to `true`. Do not edit this file while the plugin is running.

Writes use a same-directory temporary file, flush and file `fsync`, then atomic replacement. In-memory preference changes and success messages occur after replacement. A failed save leaves the previous preference in effect. This is atomic-file persistence, not a claim of tested power-loss durability or directory-entry durability on every filesystem.

Invalid JSON, unknown schema, duplicate keys, malformed UUIDs and non-boolean values stop initialization. The original file is preserved without automatic repair or overwrite. Stop the server, keep a backup, repair or deliberately move the invalid file, and restart. Moving the file intentionally resets all preferences to the default on. A failed save may leave a temporary file if cleanup is also denied; such files are never loaded.

## Development and verification

```sh
python -m pip install build
python -m build
python -m pip install dist/*.whl 'endstone==0.11.14' 'pytest>=8,<10'
python -m pytest --import-mode=importlib
```

Tests run against the **installed wheel**, the real Endstone SDK's event-registration logic and metadata constructors, and synthetic host/player fixtures. CI covers Python 3.11, 3.12, 3.13, 3.14 and 3.15. This is not a live BDS integration test, and no live-server result is claimed.

See [design and evidence](docs/design.md) and the [manual server validation checklist](docs/server-validation.md).
